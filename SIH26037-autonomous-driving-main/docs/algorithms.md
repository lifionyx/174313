# Algorithms implemented

**Prediction.** Each track follows constant velocity for 4 s at 0.2 s spacing. Occupied radius includes object size, 0.4 m safety margin, track covariance, and time-growing uncertainty. Pedestrians, two-wheelers, cattle, and low-confidence unknown objects grow more rapidly. No `predictTracksToTime` API was found in this installation.

**Risk and behavior.** The risk layer checks straight-ahead predicted separation and first predicted time to contact. It assigns LOW, CAUTION, HIGH, or CRITICAL. Behavior selects CRUISE, CAUTION, YIELD, STOP, or EMERGENCY_BRAKE and sets a speed constraint. Goal approach uses position/velocity feedback. Emergency risk is evaluated every plant step, including low-confidence close tracks, independent of the 0.5 s replanning clock. Braking retains avoidance steering when a path exists, with boundary recovery at the road edge. Emergency episodes are counted from actual brake commands.

**Free space and trajectory planning.** A Navigation Toolbox `binaryOccupancyMap` represents the known road envelope; a reference polyline follows intended x progress rather than painted lanes. Every 0.5 s the planner samples terminal lateral offsets and target speeds. It creates smooth quintic lateral shifts and acceleration-limited longitudinal profiles. It rejects candidates outside the road, entering occupied map cells, intersecting any time-indexed predicted obstacle, or exceeding the chosen lateral-acceleration/curvature checks. The cost rewards progress and penalizes offset, speed error, low clearance, abrupt curvature, acceleration, and switching sides. If no safe forward candidate remains, it commands a stop. This numeric lattice was used because its API and behavior were fully execution-tested; the installed Frenet and Hybrid A* APIs remain optional extensions.

**Control and plant.** Pure pursuit computes steering from a preview point, clipped at 0.45 rad. Longitudinal feedback and goal position feedback command acceleration or braking within configured limits. `stepVehicle` integrates a kinematic bicycle; ego pose is never copied from the planned path. Collision checks compare ego geometry with actual actor truth only for scoring and termination.

**Perception limits.** Synthetic sensor generators model statistical detections and point clouds from simulator actor poses. Camera and radar measurements create/refresh tracks; lidar points corroborate geometry. Some radar clutter is filtered against the known road corridor. This is a sensor simulation, not a learned IDD perception model. The hand-built tracker is preferable for this reproducible baseline to untested JPDA tuning.
